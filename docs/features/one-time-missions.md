# ماموریت‌های یک‌بار انجام

## خلاصه
ماموریتهایی **شرطی** که هر کاربر فقط یک‌بار می‌تواند کلیم کند — برای هدایت به اقدامات ارزشمند (پروفایل، فالو، خرید).

## مسئله
فعالیت‌های مهم (تکمیل پروفایل، عضویت شبکه، خریدبلیت) یک‌بار نیاز دارند اما در نرمال‌ترین استفاده بدون تشویق نشوند.

## انواع (۴ عنوان)
| نوع | شرط | پاداش |
|-----|------|-------|
| تکمیل پروفایل | عکس + نام + بیو + ... | سکه + امتیاز |
| امتیاز اپ | ورود مارکت + امتیاز دادن | سکه |
| Open Link | باز کردن لینک خاص (فالو/عضویت) | سکه + امتیاز |
| بلیت سینما | خرید بلیت در فیچر سینما | سکه |

## نمایش و UX
- **تب جداگانه** یا دسته خاص در کالب
- وضعیتها: *درحال / انجام‌شده / کلیم‌شده*
- دکمه کلیم فعال پس از تأیید شرط
- پاداش فوری پس از کلیم

## الزامات فنی
- **Backend**: تعریف شرط هر مأموریت + اعتبارسنجی + ثبت وضعیت + اعمال پاداش
- **Frontend**: نمایش لیست + تشخیص انجام شرط + کنترل دکمه کلیم

## پیاده‌سازی
- ✅ **اپ**: هر دو ویژگی (تکمیل پروفایل + Open Link)
- ✅ **وب**: تکمیل پروفایل (فقط این دو)
- ⏳ **سینما**: بلیت‌خریداری (در حال توسعه)

## چالش‌ها
- **Link Open**: دقت پایین در تأیید انجام (فالو دنبال نشود)
- **سوءاستفاده**: حذف و خرید مجدد بلیت برای جایزه دوبار
- **Marketplace**: تشخیص امتیاز دادن نیازمند Integration

## KPI‌ها (۱ ماه)
- نرخ تکمیل پروفایل: **۷۰%** کاربران جدید
- نرخ کلیم اپ: **۵۰%** کاربران فعال
- کلیک لینک شبکه: **۶۰%**
- کلیم بلیت: **۳۰%** کاربران سینما

## Release (۵ هفته)
1. طراحی UI → هفته ۱
2. Backend (منطق + ثبت + پاداش) → هفته ۲
3. Frontend (نمایش + تعامل) → هفته ۳
4. QA → هفته ۴
5. انتشار + اطالع‌رسانی → هفته ۵

## ریسک
- عدم اطمینان از انجام واقعی برخی لینکها → پاداش پایین‌تر یا اسکرینشات
- سوءاستفاده بلیت → بررسی یکتا بودن
- عدم تعامل Marketplace → راهنمای دستی
